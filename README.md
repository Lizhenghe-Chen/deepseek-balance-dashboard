## ✨ 功能

| 模块 | 说明 |
|---|---|
| 💰 **账户余额** | **页面主卡**：整行放大显示，附带「余额正常 / 偏低 / 不足」状态徽章与「最近一次变动」，并拆分赠送 / 充值；同时持有两种币种时显示「另有 USD $x」 |
| 📉 **本月消费** | 按自然月累计；中途充值不会冲抵消费 |
| 🔥 **本日消费** | 官方与观测只取**较大值**，避免导出快照让当天数字变小；副标题给出「每 ¥0.01 一档 · 最近一笔 HH:MM」。若第一笔跨了零点，会标注「含隔夜缺口」 |
| 📊 **日均与预测** | 日均按「从第一个有数据的那天到今天」计算（中间没打开的日子也计入）；「预计可用 N 天」给出**区间**而非单一整数，样本不足 3 天时直接说明「样本不足」而不做预测 |
| 📈 **消费趋势** | 累计消费阶梯线，**跨度跟着数据走**：有多少记录就画多少，不做固定一周。`−` / `＋` 可连续缩放（最小 2 小时），点中间的文字回到全部。窗口 ≤30 小时按分钟定位（今日曲线），更长自动切成「每天一级」的阶梯；悬停可看每一笔的具体金额 |
| 🕐 **峰谷时段** | 顶栏徽章实时显示「高峰 2× 单价 / 空闲 5 折」（北京时间周一至周五 09–12、14–18 为高峰，节假日与周末全天空闲） |
| 🧾 **官方用量** | 可选，未导入时只占一行：拖入或选择控制台导出的 `amount-*.csv` / `cost-*.csv`，**已过去的日子自动改用官方日成本**（精确到分），同时得到分模型成本、缓存命中率、请求数与同区间对账差。每次导入单独列一条（文件名 / 账户 / 日期范围 / 金额），可逐条删除并支持 8 秒内撤销，删掉后主数据同步回退 |
| 🔔 **低余额提醒** | 可选的浏览器桌面通知，余额低于自定义阈值时提醒一次（仅页面打开时生效） |
| 🔄 **自动刷新** | **前台每分钟采样**（分钟级曲线才有落点精度），切到后台降到 5 分钟；回到前台且已超周期会立刻补采。每次请求都会记一条采样，余额没变也记 |
| ⚡ **手动刷新** | 顶栏 `↻` 即时拉取最新余额（请求带 `no-store`，不吃浏览器缓存），完成后重新计时 |
| 🔁 **多账户** | 每个 Key 一份独立历史，换 Key 不清空、不互相做差。`⚙️` 里列出所有账户（名字 / 币种 / 条数 / 覆盖天数 / 最后余额），可重命名、可逐个删除；粘贴某个账户的 Key 即切回它 |
| 💾 **历史备份** | 一键导出**全部账户** + 官方用量为 JSON，导入时按档案合并；可跨浏览器、跨设备迁移 |
| 🔒 **隐私** | Key 只存在于本标签页内存与 `sessionStorage`（不写 `localStorage`），只在请求余额时发给 `api.deepseek.com` |

## 🚀 快速开始

**方式一：直接访问在线版**（推荐）

<https://bunnychen.top/deepseek-balance-dashboard/>

**方式二：克隆到本地**

```bash
git clone https://github.com/Lizhenghe-Chen/deepseek-balance-dashboard.git
```

1. 双击打开 `index.html`（无需服务器、无需构建）
2. 在弹出的窗口里填入 API Key（`sk-` 开头，[在这里创建](https://platform.deepseek.com/api_keys)）
3. 保存即可看到余额与图表

> 用 `python -m http.server` 之类的本地服务器打开同样可以。

两种方式功能完全一致。数据全部保存在**你自己的浏览器**里：在线版与本地版属于不同来源（origin），历史互不相通，跨设备 / 跨浏览器请用导出 / 导入 JSON 迁移。

## 🌐 部署到 GitHub Pages

本仓库本身就是可直接托管的静态站点（根目录 `index.html` + `.nojekyll`），没有构建步骤：

1. 仓库 → **Settings** → **Pages**
2. **Source** 选 **Deploy from a branch**，分支 `main`，目录 `/ (root)`，保存
3. 约一分钟后访问 `https://<用户名>.github.io/<仓库名>/`；之后每次 `git push` 自动重新发布

> 本仓库的账号已给 Pages 绑定自定义域名 `bunnychen.top`（项目站点沿用它，形如 `https://bunnychen.top/<仓库名>/`），因此 `https://lizhenghe-chen.github.io/deepseek-balance-dashboard/` 会 301 跳到 `https://bunnychen.top/deepseek-balance-dashboard/`，两者等效。

`.nojekyll` 让 Pages 跳过 Jekyll 处理，文件按原样发布。

浏览器能否直连 DeepSeek：已实测该接口对本站点实际来源（`https://bunnychen.top`）的预检请求回显 `Access-Control-Allow-Origin` 并允许 `Authorization` 头，因此 Pages 版可以直接调用，无需任何代理或后端。

### 公开托管时需要注意的三点

- **站点是公开的，但数据不是**。任何人打开这个网址看到的都是同一份前端代码，各自拥有属于自己的浏览器本地数据；仓库和页面里没有任何密钥。
- **同账号的 Pages 站点共享一个 origin**。站点实际来源是 `https://bunnychen.top`（或未绑自定义域名时的 `https://<用户名>.github.io`），这是一个**账号级** origin：`localStorage` / `sessionStorage` 只按 origin 隔离，不按仓库隔离，因此本站与同账号的其它 Pages 项目（若本站与博客等共用同一域名，也包括博客）共享同一份浏览器存储：
  - 余额历史（`ds_history_v3`）**任何同源页面、任何标签页**都能读到（内容只有余额快照与 Key 指纹，不含 Key），也能被清空或篡改；
  - API Key 存在 `sessionStorage`（仅当前标签页），但如果你在**同一标签页**里跳转到该 origin 下的其他页面，对方在这次会话中可以看到它；
  - 同源页面还可以为整个 origin 注册 Service Worker。**因此同源站点的安全性等于其中 weakest 的那一个**。
  - 在意的话：给本仓库的 Pages 单独配置一个子域名（Settings → Pages → Custom domain，例如 `dash.bunnychen.top`），它就拥有独立 origin，与博客等页面彻底隔离；也可以把 `index.html` 下载到本地双击打开（`file://` 是独立来源，任何网站都读不到它的存储）。
- **必须走 HTTPS**。Pages 默认提供。CSP 的作用是**收窄脚本能主动外发的通道**：`connect-src` 只允许 `api.deepseek.com`，且没有 `eval` / `new Function`。但它不是"被注入也安全"的保证，具体边界见下方「隐私与安全」。输入框用 `autocomplete="new-password"` 降低被密码管理器收录的概率。

> 也可以部署到 Cloudflare Pages / Netlify / Vercel 等任意静态托管，行为一致。

## 🔐 隐私与安全

| 问题 | 答案 |
|---|---|
| Key 会存到哪里？ | 仅内存 + 当前标签页的 `sessionStorage`（不写 `localStorage`）。注意：`sessionStorage` **不是纯内存**——Chromium / Firefox 为支持「会话恢复」会把它写盘，浏览器崩溃恢复或「继续上次会话」时 Key 可能被还原；正常关闭标签页后其它页面读不到 |
| Key 会被上传吗？ | 只会发给 DeepSeek 官方余额接口 `https://api.deepseek.com/user/balance`（`Authorization: Bearer`），不发往任何第三方；页面没有后端、没有统计 |
| 设置面板里能看到明文 Key 吗？ | 不会。面板只显示 `sk-••••••1234` 这样的掩码与指纹，输入框永远为空，关闭面板即清空 |
| 有第三方脚本吗？ | 只有 Chart.js（jsDelivr CDN，带 SRI 完整性校验，哈希已核对）。页面会因此向 jsDelivr 发起一次请求（对端可见 IP / UA，`referrer` 已设为 `no-referrer`） |
| 历史数据在哪？ | 浏览器 `localStorage` 的 `ds_history_v3` 键（多账户，每份含余额快照与 Key 指纹，不含 Key） |
| 导入的 CSV 会被上传吗？ | 不会。文件只在本地用 `File.text()` 解析，仅保存文件名、账户 `user_id`、Key 名称、日期、模型 / 类型 / 数量 / 价格等用量信息到 `ds_usage_v3`；`api_key` 列整列跳过，不读取也不落盘 |
| CSP 能防住 XSS 吗？ | **不能当成保证**。它挡住了 `fetch` / XHR / WebSocket / beacon / 表单 / 图片外发，只放行 `api.deepseek.com`；但 `script-src` 含 `'unsafe-inline'`（页面用内联 `onclick`），`connect-src` **不管顶层跳转**（`location='…?k='` 能带走 Key），且 CSP 写在 `<meta>` 里、托管方不下发 CSP 响应头——能改页面的人可以连 CSP 一起删掉。真正的防线是"页面里没有任何 HTML 注入点"（全部走 `textContent`） |
| 公开托管会泄露 Key 吗？ | 托管方拿到的是同一份公开代码，看不到你在浏览器里输入的内容；但**同账号的其他 Pages 站点与本站同源**，它们（或浏览器扩展、DevTools）在特定条件下能读到 `sessionStorage`。要高保障：用独立子域，或把 HTML 下到本地用 `file://` 打开 |
| 刷新会丢数据吗？ | 不会。刷新保留 Key（`sessionStorage`）与历史（`localStorage`），并立即重新拉取一次余额 |
| 换 Key 会丢历史吗？ | 不会。每个 Key 一份独立档案，粘贴新 Key 只是新建或切回档案，任何历史都不会被清掉；要删得手动在 `⚙️` 里删（两次确认） |

历史里保存的是 Key 的 **djb2 指纹**（用于区分不同账号），不是 Key 本身。

## 🔁 多账户 / 换 Key

1. 点顶栏 `⚙️`，面板顶部显示**当前账户**（名字 + Key 掩码 + 指纹 + 历史条数），下面列出所有账户的历史概况。
2. **换 Key 不再询问、也不清空任何东西**：
   - 粘贴一个**已存在**的 Key → 直接切回它那份历史；
   - 粘贴一个**新** Key → 新建一份档案，从这一刻开始记录，其它账户原样保留。
3. 每个账户可以点名字**重命名**（默认用导入 CSV 时的 `user_id`，没有就用指纹前 6 位），也可以逐个**删除**（点两次确认）。
4. 点「清除并退出」只清除 Key，不删任何历史；重新粘贴对应 Key 即可继续。
5. 最多保存 **5 个账户**，每条档案保留最近 **60 天**。

> ⚠️ **同一账户的多个 Key 共享同一个余额池**。它们各自独立记一份观测序列是没问题的（不会再互相做差产生假消费），但**不要把它们的消费相加**。如果你要的是"一个账户一个总额"，就只留一个 Key 的记录。

> 币种不同会按 `指纹|币种` 各存一份，CNY 与 USD 的历史不会混算，也不会互相覆盖。

## 📏 测量精度

余额接口只返回 **2 位小数的字符串**，这是所有消费数字的物理下限：

| 量 | 精度 |
|---|---|
| 最小刻度 | ¥0.01；单次读数误差 ±¥0.005 |
| 本月合计（链式求差） | 误差 **≤ ¥0.01**（中间误差精确抵消，与天数无关） |
| 单个"日" | 每天重新起链 → 各自 ±¥0.01，**还会叠加**"页面未打开期间的整段消费记到重开那一刻"的缺口 |
| 日消费 ¥0.29 | 一个台阶要等约 49.7 分钟，分钟轴上会是一段直线；这个量级适合看日/月，不适合看分钟 |
| 日消费 ¥7 | 一个台阶约 2 分钟，分钟轴上勉强能看出阶梯 |
| 台阶落点 | 前台每分钟采样 → 每笔的位置误差约 ±1 分钟；后台 5 分钟采样 → ±5 分钟 |
| 日消费 < ¥0.005 | 可能整天显示 ¥0.00，图表 tooltip 会说明「低于可测精度」 |

因此「预计可用 N 天」以**区间**呈现（例如 `85–87 天`）：只要日均偏一个刻度，天数就会大幅跳动。样本不足 3 天时页面不给预测，只写「样本不足」，避免用一天的消费外推出「还能用两百多天」这种伪精度。需要精确到分时，导入控制台「用量信息」导出的 CSV 即可——已过去的整天会改用官方日成本，主卡与图表都会跟着变。

## 📐 消费是怎么算出来的

官方文档明确：`total_balance = granted_balance + topped_up_balance`，且扣费时**优先扣赠送额度**。因此：

- ✅ 用 `total_balance` 跟踪余额。若只看 `topped_up_balance`，赠送额度没花完时消费会一直显示 **0**。
- ✅ 消费 = **相邻两次采样余额差值的累加**，而不是「当天首尾差」。后者一旦中途充值，当天消费会被抹成 0。
- ✅ 充值（余额上升）单独统计为「期间充值」，绝不冲抵消费。
- ✅ **导入官方 CSV 后按天覆盖**：已过去的整天改用官方日成本（`cost-*.csv` 的金额，或 `amount-*.csv` 的 `price × amount`），没有官方数据的天仍用观测值。**今天取官方与观测的较大值**——官方文件只到导出那一刻、观测只覆盖页面打开之后，取较大值才不会让当天数字变小；另一路数字降级为「本日消费」下方的一行备注。
- ⚠️ 官方数据是**导出时刻的快照**，不会自动更新；看到新的消费要重新导出并导入。同一账户重复导入同名文件会更新那一条批次，不会翻倍。
- ⚠️ 导入可能来自不同账户：每个批次都显示 `user_id`，多个账户混在一起时会给出提示，删掉不属于当前账号的那条，主数据里对应日期会立刻退回观测值（或被更早的批次接管）。
- ⚠️ 官方日按**本地日期**归属（`start_time_iso` 带时区偏移，换算到浏览器本地时区）；币种与当前账号不一致时不会合并。
- ⚠️ **隔夜变动会整体记入"重新打开页面"的那一天**：那一笔会画在当天的第一个点上，并在副标题标注「含隔夜缺口」，无法真的拆分到前一晚。
- ⚠️ 日均的分母是"从第一个有数据的那天算到今天"的**日历天数**，中间没打开页面的日子也计入。
- ⚠️ 官方自 2026-08 起实行**峰谷价**（空闲价 = 高峰价的一半，高峰为北京时间周一至周五 09–12、14–18），所以同样多的 token 在不同时段花费不同，日消费忽高忽低属于正常。

**已知失真**

- 赠送额度过期也会让 `total_balance` 下降，会被记为当天消费。
- 页面未打开期间无法采样：总量仍会体现在下一次采样里，但无法得知具体发生在哪一刻（在今日曲线里表现为第一个点跳得特别高，并标注「含隔夜缺口」）。
- 余额精度为 2 位小数，因此小于 `¥0.01` 的消费不可见；详见上面的「测量精度」。
- `localStorage` 写满时会先丢最老账户的一半采样，再不行丢掉整份最老账户，链式差值因此出现硬缺口（极少数情况）。
- 多账户档案之间**没有关联**：同一账户的多个 Key 各记一份，消费不可相加；不同账户之间也不做任何合并。

## 🧱 数据模型

```json
{
  "k": "892efcc3",
  "cur": "CNY",
  "lastPoll": 1792811247065,
  "s": [
    { "t": 1792809600000, "b": 561.77 },
    { "t": 1792811247065, "b": 560.52 }
  ]
}
```

每份档案的结构：

| 字段 | 含义 |
|---|---|
| `k` | API Key 的 djb2 指纹（**不是账户 ID**，同账号换 Key 会得到不同指纹） |
| `name` | 你起的名字；为空时回退到 `userTag` 或指纹前 6 位 |
| `userTag` | 导入官方 CSV 时记录下来的 `user_id`，是唯一能跨设备识别的账户线索 |
| `cur` | 币种，一份档案只对应一种（CNY 或 USD） |
| `lastPoll` | 上次轮询时间，同时用于判断档案是否已过期 |
| `s` | 采样点数组：`t` 为毫秒时间戳，`b` 为余额。**每次请求都追加**；48 小时内保留完整采样（分钟级定位），更早的只保留余额变动的点 |

外层是 `{ "active": "指纹|币种", "accounts": { "指纹|币种": 档案 } }`。每条档案保留最近 60 天，最多 5 份；写满配额时先丢最老的那份。旧版 `ds_history_v2`（单档案）与它的备份槽会在首次打开时自动并成档案，一份都不会丢。

导出的 JSON 带上全部账户与官方用量；导入时按档案合并（同一天以时间戳并集为准）。导入旧版单档案 JSON 同样可用。

其它本地键：

| 键 | 内容 |
|---|---|
| `ds_api_key` | 仅 `sessionStorage`，明文 Key，关闭标签页失效 |
| `ds_history_backup` | v2 时代的一次性备份槽，仅用于迁移时并入档案，之后不再写入 |
| `ds_usage_v3` | 导入的官方用量：按**导入批次**保存文件名、账户 `user_id`、Key 名称、币种与原始用量行；**不含 `api_key` 列**。只保留最近约 13 个月的批次，写满时先丢最老的一次导入。旧版 `ds_usage_v2` / `ds_usage_v1` 会自动迁移成一个批次 |
| `ds_alert` | 低余额提醒的阈值与「已提醒」标记 |

## ❓ FAQ

<details>
<summary><b>为什么一开始图表是空的，或者消费显示 0？</b></summary>

消费由两次采样的差值推导，至少需要两次「余额发生变化」的采样。刚设置好 Key 时只有一个点，稍等一轮刷新即可。
</details>

<details>
<summary><b>关掉浏览器还会继续记录吗？</b></summary>

不会。这是纯前端方案，没有后台进程；这是它保持「零部署」的代价。
</details>

<summary><b>换了 API Key，历史会怎样？</b></summary>

什么都不丢。每个 Key 对应一份独立档案：

- 粘贴**已有的** Key → 直接切回那份历史；
- 粘贴**新的** Key → 新建一份，从此刻开始记录，旧的原样保留。

要注意两点：① 账户名默认取指纹前 6 位，建议在 `⚙️` 里改成你能认出来的名字（导入过官方 CSV 的话会自动用里面的 `user_id`）；② 同一账户的多个 Key 共享余额池，两份档案的消费**不能相加**。
</details>

<details>
<summary><b>我的账号同时有 CNY 和 USD，显示哪一个？</b></summary>

页面**只跟踪一种币种，绝不求和**。规则是：优先沿用已记录的币种（避免接口数组顺序变化导致抖动），否则取有充值余额的那个，再否则取有余额的那个。另一种币种会以「另有 USD $x」的形式显示在主卡副标题里。若接口只返回另一种货币，会切到 `指纹|USD` 那份档案（没有就新建），CNY 的历史原样保留，并在状态栏提示。
</details>

<details>
<summary><b>怎么让消费数字更准？</b></summary>

去 <https://platform.deepseek.com/usage> →「用量信息」→ 选时间范围 → **导出**，解压得到 `amount-*.csv` 与 `cost-*.csv`，在本页「官方用量」面板里导入（可多选两个文件，也可以直接把文件拖到面板里）。导入后：

- **本月消费、日均、预测、图表柱子**里已过去的整天会改用官方日成本，副标题会标注「官方 N/M 天」，避免整月被误读为精确值；
- 面板给出官方本月/今日成本、缓存命中率、请求数、分模型成本，以及「官方 vs 观测」的对账差；
- 今天仍用实时观测，若与官方快照不同会同时列出两个数字。

只导 `amount-*.csv` 也能算成本（用文件里的 `price × amount`），但该文件不带币种列，此时按当前账号的币种理解；导 `cost-*.csv` 则使用官方金额与币种（同一天可能分 Paid / Granted 两行，会求和）。

**每次导入都会在面板下方单独列一条**：文件名、账户（`user_id`）、Key 名称、覆盖的日期范围、天数 / 行数、金额、导入时间。所以：

- 导错了账户（`user_id` 不同）能一眼看出来 —— 面板会提示「检测到 N 个不同账户的用量文件」，点那条后面的「删除」即可，主数据里对应的日期会**立刻回退**成观测值（若还有更早的导入覆盖同一天，会退回到那份的值）。
- 同一账户重复导入同名文件 = 更新那一条，不会并列、也不会翻倍。
- 币种与当前账号不一致的文件会标「未合并」，只列出、不影响主数据。
- 删错了也别慌：删除后状态栏会出现「撤销」，8 秒内点一下就恢复（「全部删除」同样可撤销）。
- 没导入时这块只占标题一行，不会占掉首屏；导入后才会展开完整面板。
- 全部删完后主数据回到纯观测口径。

文件里的 `api_key` 列**不会被读取**，导入数据里不会出现任何 Key。
</details>

<details>
<summary><b>低余额提醒什么时候会响？</b></summary>

在 `⚙️` 面板里填阈值并点「开启 / 更新」，浏览器会请求通知权限。之后余额低于阈值时发一次桌面通知，余额回升后再跌破会重新提醒。

限制（页面会如实标注）：只在页面打开时生效；后台标签页可能延迟到约 1 分钟；手机锁屏 / 关闭浏览器不会触发；iOS Safari 需要把页面「添加到主屏幕」且走 Service Worker，本页用的是普通 `Notification`。想要"关掉浏览器也能提醒"，只能用服务端方案（例如 GitHub Actions 定时轮询）。
</details>

<details>
<summary><b>提示「图表库未加载」？</b></summary>

说明 Chart.js 没能从 CDN 取到（离线或被网络策略拦截）。此时数据刷新、导出、用量导入仍然可用。若要改成完全离线：把 `chart.umd.js` 下载到同目录，改掉 `<script src>`，并且**把 CSP 的 `script-src` 加上 `'self'`**（当前只允许内联脚本与 jsDelivr，直接换成本地文件会被 CSP 拦下）。
</details>

<details>
<summary><b>图表的跨度是怎么定的？</b></summary>

默认就是**你实际记录到的范围**：只有 2 小时数据就画 2 小时，有 6 天就画 6 天，不会强制一周。

- 想看得更细：点 `＋` 收窄跨度（最小 2 小时），`−` 放宽，点中间的文字（如「全部 6 天」）回到全程；
- 跨度 ≤ 30 小时时按**采样**画（台阶落点精确到分钟）；更长的窗口自动按**天**聚合，每天一级台阶，其中用官方 CSV 覆盖过的日子取官方值；
- 采样很稀的时候（比如页面只开过几分钟），台阶会很大——这不是 bug，是余额只有两位小数的必然结果。
</details>

<details>
<summary><b>为什么前台 1 分钟、后台 5 分钟？</b></summary>

前台 1 分钟是为了让「今日消费曲线」的台阶落点准到 ±1 分钟；切到后台后浏览器本来就会节流定时器，继续 1 分钟只是空转，所以降到 5 分钟（同时把请求量从约 1440 次/天降到 288 次/天）。

余额只有 2 位小数，所以曲线永远是台阶：**每 ¥0.01 一跳**。日消费 ¥7 左右时大约 2 分钟一级，分钟轴有意义；日消费不到 ¥1 时，一小时才一两级，这时看日/月更合适——这不是隐藏，页面会如实显示台阶。
</details>

<details>
<summary><b>1 分钟一次会不会把 API 调爆？</b></summary>

整天开着标签页约 1440 次/天。项目里对 429 做了退避：触发限流后先退到 5 分钟，连续触发最长退到 15 分钟，不会死循环重试。如果你更在意请求量，把 `POLL_VISIBLE` 改回 `5 * 60 * 1000` 即可，曲线仍然可用，只是台阶落点变粗。
</details>
